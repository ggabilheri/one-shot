## 2. Objetivo da Task
Implementar a camada de persistência (`BankTransactionRepository`), as regras de negócio (`BankTransactionService`) e a interface RPC (`BankTransactionEndpoint`) no Serverpod para validar o arquivo OFX contra a conta selecionada, persistir as transações sem duplicidade e permitir a conciliação.

## 4. Detalhes de Implementação
- [x] Implementar `IBankTransactionRepository` e `BankTransactionRepository`:
  - `Future<List<BankTransaction>> findByAccountId(Session session, UuidValue bankAccountId, {bool? isReconciled, DateTime? startDate, DateTime? endDate})`
  - `Future<Set<String>> findExistingFitIds(Session session, UuidValue bankAccountId, List<String> fitIds)`
  - `Future<List<BankTransaction>> insertBatch(Session session, List<BankTransaction> transactions)`
  - `Future<BankTransaction> reconcile(Session session, UuidValue transactionId, UuidValue financialEntryId)`
- [x] Implementar `BankTransactionService`:
  - `Future<OfxPreviewResult> preview(Session session, UuidValue bankAccountId, String ofxContent)`: lê o OFX via `OfxParserHelper`, busca a `BankAccount`, compara os dados sanitizados e, se divergir, sinaliza ou lança exceção com mensagem amigável; calcula totalizadores e identifica quais `fitId` já estão no banco.
  - `Future<List<BankTransaction>> importOfx(Session session, UuidValue bankAccountId, String ofxContent)`: valida a conta bancária (rejeita com `AppException` se divergir), filtra apenas transações com `fitId` inéditos e persiste em transação única.
  - `Future<BankTransaction> reconcileTransaction(...)`: vincula a transação ao `FinancialEntry`, atualiza `isReconciled = true`, marca `FinancialEntry` como pago/recebido e preenche `paymentDate`.
- [x] Implementar `BankTransactionEndpoint` estendendo `Endpoint` delegando ao service.
- [x] Registrar no `ServiceLocator` (`injections.dart`) e rodar `serverpod generate`.
