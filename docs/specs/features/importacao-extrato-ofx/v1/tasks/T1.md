## 4. Detalhes de Implementação
- [x] Criar o schema `bank_transaction.spy.yaml` com tabela `bank_transactions`, campos `fitId`, `transactionType`, `date`, `amount`, `memo`, `isReconciled`, `reconciledAt`, relação com `BankAccount` e `FinancialEntry`, e índice único composto em `(bankAccountId, fitId)`.
- [x] Criar o schema `ofx_preview_result.spy.yaml` sem tabela (DTO) contendo `bankId`, `branchId`, `acctId`, `startDate`, `endDate`, `ledgerBalance`, `totalCredits`, `totalDebits`, `newTransactionsCount`, `duplicatedTransactionsCount`, `isAccountMatched` e `accountMatchMessage`.
- [x] Rodar `cd oneshot_server && serverpod generate` para gerar classes no servidor e cliente.
- [x] Implementar `OfxParserHelper` com:
  - `OfxRawData parse(String content)`: suportando extração de tags com e sem fechamento (`<BANKID>`, `<BRANCHID>`, `<ACCTID>`, `<LEDGERBAL><BALAMT>`, `<STMTTRN>`).
  - `(String, String?) sanitizeAgency(String agency)`: remove zeros à esquerda e caracteres não numéricos, separando agência e dígito.
  - `(String, String?) sanitizeAccount(String account)`: remove zeros à esquerda e caracteres não numéricos, separando conta e dígito.
  - `bool matchAccount(...)`: compara agência e conta sanitizadas do OFX com o cadastro de `BankAccount`.
